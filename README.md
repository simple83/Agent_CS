# Agent CS

홍익대학교 컴퓨터공학과 SNS 프론트엔드입니다.

백엔드 없이 실행하려면 `npm run dev:mock`을 사용하세요. 테스트 계정, Mock/Real 전환, 빌드 및 검증 방법은 [MOCK_GUIDE.md](./MOCK_GUIDE.md)에 정리되어 있습니다.

```sh
npm install
npm run dev:mock
```

실제 API 연결: `npm run dev:real` (`.env.real.local`에 백엔드 주소 설정 필요)

API 검사: `npm run test:api` / 전체 회귀 검사: `npm test`

확정 API 대응 범위와 실제 서버 연결 시 확인할 항목은 [확정 API 대응](#확정-api-대응)를 참고하세요.

좋아요는 게시글 상세에서만 등록·취소할 수 있습니다. 카드와 목록에는 개수만 표시합니다. 관련 상태/화면 회귀 검사는 `npm run test:likes`로 실행합니다.

게시글 Hook 상태 전환 검사: `npm run test:hooks` (백엔드 없이 최초 조회, 검색·새로고침, 요청 간 응답 순서 검증)

## 게시글 작성과 말머리

- 디시인사이드의 말머리 → 제목 → 편집 도구 → 본문 순서를 참고한 작성 화면입니다.
- 목록은 제목 중심의 표 형태이며, 말머리 필터와 제목/주제 태그 검색을 함께 사용할 수 있습니다.
- 말머리: 자유, 질문, 코드리뷰, 정보공유, 모집, 밥친구. 선택한 말머리는 기존 `hashtags`의 대표 태그 하나로 저장합니다. 새 category API 필드는 추가하지 않습니다.
- 기존 글은 질문 → 코드리뷰 → 정보공유 → 모집 → 밥친구 순서에서 처음 일치하는 태그로 분류하고, 없으면 자유로 표시합니다. 자유 태그 유무와 관계없이 같은 기준을 적용합니다.
- 서버의 `limit`/`offset`으로 20개씩 조회하고 더 불러오기를 제공합니다. 최신순·조회순 정렬을 지원합니다. 말머리와 주제 태그의 교집합은 각 페이지에 적용하며 전체 게시글 수로 표시하지 않습니다. 현재 페이지에 해당 말머리가 없어도 다음 페이지를 불러올 수 있습니다.
- 목록의 글쓰기 버튼은 선택한 말머리를 작성 화면에 전달합니다. 말머리는 URL에 남아 새로고침/뒤로가기에 유지됩니다.
- Tiptap 시각적 편집기에서 서식이 적용된 본문을 직접 작성합니다. 작성/미리보기 탭은 없으며 굵게, 기울임, 인라인 코드, 링크, 목록, 번호 목록, 인용, 실행 취소/다시 실행을 지원합니다.
- 코드블록 버튼은 작성 중인 문단을 유지하고 바로 아래에 빈 코드블록을 삽입합니다. 선택한 글자도 코드로 변환하거나 지우지 않습니다. 각 코드블록 상단 바의 오른쪽에서 언어를 선택하고, 설명을 이어 쓸 때는 ‘코드 아래에 문단 추가’를 사용합니다.
- 코드 하이라이트는 선택한 언어를 사용하며 자동 감지는 하지 않습니다. 상세 화면에서는 코드별 언어 표시와 복사를 지원합니다.
- 본문 API는 기존 Markdown 문자열을 그대로 사용합니다. 읽기는 Tiptap Markdown 확장, 저장은 ProseMirror 직렬화기를 사용하며 코드 안의 백틱과 공백을 별도 규칙으로 보존합니다. HTML/편집기 JSON을 서버에 저장하지 않습니다.
- 이미지 버튼으로 커서 위치에 사진을 삽입합니다. 저장 시 `upload://임시ID` 본문과 `images`/`image_ids`를 함께 보내고, 응답의 본문 이미지 URL과 `images`의 DB ID를 보존합니다. 새 이미지 파일은 요청당 최대 10개입니다.
- 등록 실패 시 현재 입력/첨부가 유지됩니다. 브라우저를 닫거나 다른 페이지로 이동한 뒤 복구하는 임시 저장은 아직 지원하지 않습니다.

편집 기능 회귀 검증: `npm run test:editor` (말머리, 시각적 문서의 Markdown 저장/복원, 코드 공백·백틱, 언어 변경·실행 취소, 안전한 HTML 처리, 등록 실패와 재시도).

## 내 게시글 수정·삭제

- 상세 화면 오른쪽 위의 수정·삭제 버튼은 현재 로그인한 작성자에게만 보입니다. 최종 권한 검사는 Mock/실제 서버 API가 담당합니다.
- `/posts/:postId/edit`에서 원본을 조회한 뒤 기존 작성 폼과 시각적 편집기를 재사용합니다. 새로고침과 직접 진입을 지원하고, 비로그인·타인 게시글은 편집을 막습니다.
- 저장 실패 시 현재 입력을 보존하고 요청 중에는 중복 저장을 막습니다. 성공하면 상세로 돌아가며, 취소는 저장하지 않고 돌아갑니다. 다른 화면으로 이동한 뒤의 임시 저장은 지원하지 않습니다.
- 수정하지 않은 태그는 PATCH에서 생략합니다. 말머리를 직접 변경하면 기존 말머리 태그들을 선택한 하나로 정리하고 나머지 주제 태그는 유지합니다.
- 수정 화면에서도 이미지를 추가하거나 본문에서 제거할 수 있습니다. 기존 이미지 DB ID를 `keep_image_ids`로 보내며 본문에서 제거한 이미지는 유지 목록에서도 제외합니다. 변경하지 않은 이미지는 유지합니다.
- 삭제는 확인창에서 확인한 뒤 요청합니다. 성공하면 목록으로 이동하고 실패하면 상세에 오류를 표시합니다. API는 소프트 삭제이며 복원 UI는 없습니다.
- 수정 화면도 기존 상세 조회 API를 사용하므로 진입 시 조회수가 증가할 수 있습니다. 조회수 집계 정책은 별도 작업으로 보류했습니다.

회귀 검사: `npm run test:management` (Mock 기반 수정·삭제, 직접 진입, 계정 변경, 원본 보존, 실패·중복 요청).

## 댓글·대댓글과 코드블록

- 상세 화면 아래에서 댓글을 조회하고 로그인 후 작성·답글·본인 댓글 수정·삭제를 할 수 있습니다. 답글 입력은 확정 계약에 따라 부모 댓글 아래 한 단계만 지원합니다.
- 댓글 영역 상단 오른쪽에 새로고침·작성 버튼을 배치하고, 작성 편집기도 목록 위에서 열어 긴 댓글 목록을 끝까지 내려가지 않아도 작성할 수 있습니다.
- 댓글 작성·답글·수정은 일반 텍스트와 코드블록만 제공하는 간단한 편집 모드를 사용합니다. 굵게·기울임·링크·목록 등의 서식 도구와 관련 단축키/자동 서식은 비활성화합니다. 코드블록 버튼은 현재 문단 아래에 빈 블록을 삽입하고, 블록 상단 오른쪽에서 언어를 선택합니다. 본문은 JSON의 `content`에 Markdown 문자열로 저장하며 이미지는 지원하지 않습니다.
- 게시글과 댓글의 코드는 표시·문법 강조·복사만 지원합니다. 실행 버튼, eval/Function 실행 경로, 코드 실행 서버 연동은 추가하지 않습니다. 원시 HTML은 텍스트로 처리하며 iframe·실행 가능한 임베드를 생성하지 않습니다. 이미지는 게시글의 Markdown 이미지에만 허용하고 댓글에서는 차단합니다.
- 댓글 등록에 성공하면 편집기를 닫고 ‘댓글 작성’ 버튼으로 돌아갑니다. 다시 열면 빈 초안으로 시작합니다. 저장 실패는 편집기와 초안을 유지하고, 저장 성공 뒤 목록 갱신만 실패하면 편집기를 닫되 목록 갱신 오류를 별도로 표시합니다. 댓글 조회 실패는 게시글 본문을 유지하며 변경 요청은 자동 재전송하지 않습니다.
- 댓글 목록에서 집계를 갱신하므로 댓글 작성·수정·삭제·새로고침은 게시글 상세 조회수를 증가시키지 않습니다. 전체 목록 응답 기준이며 페이지네이션 도입 시 서버 total 계약이 필요합니다.
- Mock도 작성자·게시글 소속·삭제 상태를 검사합니다. 기존 Mock 저장소에는 댓글 필드만 추가하고 사용자 글·첨부·좋아요·세션은 보존합니다. 이전의 예시 댓글 수는 실제 댓글 데이터에 맞춰 정리됩니다.
- 댓글 길이 제한은 Markdown 포함 5,000자입니다. Python 문자열과 같이 유니코드 코드 포인트로 세므로 이모지의 UTF-16 길이로 잘못 제한하지 않습니다. 서버의 입력 제한·도배 방지를 대체하지 않습니다.

부모 댓글을 삭제해도 답글은 유지합니다. 서버의 `is_deleted: true`, `content: null` 응답을 삭제 안내로 표시하고 삭제된 댓글은 집계에서 제외합니다. 삭제 후 목록 재조회에 실패해도 답글은 화면에서 제거하지 않습니다.

실제 댓글 API는 중첩 `replies` 응답을 검증한 뒤 내부 평면 목록으로 변환합니다. 다른 글의 댓글, 상충하는 중복 ID, 잘못된 부모 관계와 2단계를 넘는 답글을 거부합니다. 기존 Mock 데이터의 블라인드 필드는 호환용 내부 모델에만 남기고 확정 API에 없는 필드를 요청하거나 요구하지 않습니다.

회귀 검사: `npm run test:comments` (Mock/HTTP 계약, 코드블록 작성·언어 선택, 수정·삭제·권한, 원문 보존, 오류·응답 순서, HTML과 위험 링크 처리).

## 게시글 기능 파일 위치

화면을 수정할 때는 아래 역할별 폴더에서 시작합니다. 전용 CSS는 사용하는 컴포넌트 옆에 둡니다.

```text
src/features/post/
├─ components/
│  ├─ list/          # PostList, PostCard: 목록과 요약 카드
│  ├─ write/         # PostForm, PostEdit: 작성·수정 폼과 수정 권한 확인
│  ├─ detail/        # PostDetail, PostLikeControl, PostOwnerActions: 상세·좋아요·작성자 도구
├─ styles/           # PostLayout: 목록·작성 화면 공통 배치
├─ hooks/            # 조회·작성·수정·삭제·좋아요 상태와 처리 흐름
├─ services/         # Mock/Real API
├─ types/            # 게시글과 API 데이터 타입
├─ utils/            # 말머리·언어 목록 등 공통 보조 함수
└─ mocks/            # 예제 게시글 데이터
```

`PostCard`는 현재 표 형태의 목록에서는 사용하지 않는 재사용 카드입니다. 댓글은 `features/comment/`의 components/hooks/services/types/utils에 분리합니다.

실제로 게시글과 댓글이 함께 쓰는 편집기·렌더러는 `shared/components/richText/`로 이동했습니다. `RichTextEditor.tsx`는 입력, `MarkdownContent.tsx`는 안전한 표시와 코드 복사, `visualEditor.ts`는 문서 변환, `CodeBlockEditor.tsx`는 블록별 언어 선택을 담당합니다. 전용 CSS와 Context도 같은 폴더에 있습니다. 각 기능의 폼·권한·API 로직은 계속 해당 feature에 둡니다.

## CSS 수정 기준

- `src/index.css`는 기본 글꼴·줄 높이·박스 계산만, `src/styles/tokens.css`는 공통 색상·글꼴과 다크 모드 변수를 관리합니다. 전역에서 제목·코드·입력 요소의 디자인을 지정하지 않습니다.
- 각 컴포넌트는 자신의 `*.module.css`를 직접 가져옵니다. 부모는 배치를 관리하고 자식의 모든 `button`, `label`, `select`를 일괄 선택하지 않습니다. 공용 입력·버튼은 `Controls.module.css`의 클래스를 해당 요소에 명시적으로 부여합니다.
- 작성·상세·댓글의 문단·강조·목록·코드 표현은 `RichText.module.css`, 코드 상자와 조작 바는 `CodeBlock.module.css`를 공유합니다. 편집기 전용 크기·도구 모음·포커스는 `RichTextEditor.module.css`에 둡니다.
- `CodeSyntax.module.css`는 highlight.js GitHub Dark 테마를 로컬 루트 아래로 제한한 파일입니다. `hljs-*` 클래스 이름은 라이브러리 계약이므로 유지하고, 라이브러리 갱신 시 이 테마도 확인합니다. 외부 테마 CSS를 전역으로 중복 불러오지 않습니다.
- 스타일 검증에서는 목록→작성→상세 이동과 직접 진입, 편집기 단독 배치, 밝은·어두운 테마, 모바일 폭, 키보드 포커스를 확인합니다. CSS Modules는 이름 충돌을 줄이지만 상속이나 넓은 자식 선택자까지 차단하지는 않습니다.


## 확정 API 대응

2026-11-24에 전달받은 `api_상세_02.md`를 기준으로 기존 화면에서 사용하는 Auth·Post·Comment 계약을 반영했습니다. 사용자 프로필·회원가입·탈퇴 등 아직 화면이 없는 API의 신규 UI는 구현하지 않았습니다.

| 영역 | 적용 내용 |
| --- | --- |
| 게시글 응답 | 목록 `PostSummary`와 상세 `PostEntity` 분리, `images: { id, image_url }[]` 사용 |
| 이미지 작성·수정 | Markdown의 `upload://ID`와 파일을 순서대로 전송, `keep_image_ids`로 기존 이미지 유지·삭제 |
| 목록 | `sort`, `limit`, `offset` 지원, 페이지 단위 말머리·태그 교집합과 더 불러오기 |
| 입력 제한 | 제목 1~200자, 태그 1~50자·소문자·중복 제거, 새 이미지 요청당 최대 10개 |
| 좋아요 | 변경 응답의 `post_id`, `like_count`, `is_liked`를 검증해 서버 집계 반영 |
| 댓글 | `author_*` 응답을 화면 모델로 변환, 최대 5,000자, 삭제 부모의 null 본문 처리·답글 보존 |
| 인증 | refresh 응답에서 access token만 갱신, refresh token 보존, 무효 세션 로그아웃의 401 처리 |
| Mock | 같은 계정의 단일 세션, 페이지 조회·이미지 참조 규칙·부모 댓글 삭제 정책 반영, 구버전 첨부 데이터 이관 |

`tests/fixtures/api-contract.json`은 전달된 확정 문서의 응답 예시 22개를 추출한 고정 자료입니다. 자동 검사는 이 응답을 실제 서비스 파서에 전달하고, React·Tiptap 화면과 Mock 저장소까지 연결해 회귀를 검사합니다. `npm test`는 메모리 사용을 줄이기 위해 테스트 파일을 순차 실행하며 시연 패키지 전용 검사는 포함하지 않습니다.

실제 서버 연결은 별도 확인이 필요합니다. `.env.real.local`의 주소를 설정한 후 CORS와 인증, multipart 이미지 업로드 및 Presigned URL 표시·만료, 기존 이미지 유지·삭제, 부모 댓글 삭제 후 답글 반환을 확인해야 합니다. 자동 검사는 실제 서버나 S3에 연결하지 않습니다. Mock의 이미지 합계 1MB 제한은 브라우저 저장소를 위한 별도 제한입니다. 토큰 자동 갱신·변경 요청 자동 재전송은 추가하지 않았습니다.
